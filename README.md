# Prompt Coach

Python으로 실행하는 로컬 프롬프트 작성 도우미입니다. **작성 → 필요하면 Support → 복사해서 AI에 사용**이 기본 흐름입니다. 점검과 점수는 선택 기능이며 작성이나 사용을 막지 않습니다.

## 실행

Python **3.11 이상**이 필요합니다. Python 표준 라이브러리만 사용하므로 `pip install`은 필요하지 않습니다.

1. ZIP을 압축 해제합니다.
2. Windows에서는 **start.bat**을 실행합니다. macOS/Linux에서는 `python3 run.py`를 실행합니다.
3. 브라우저에서 `http://127.0.0.1:8765`가 열립니다. 자동으로 열리지 않으면 주소를 직접 입력하세요.
4. 바로 프롬프트를 작성합니다. 필요한 경우 프로젝트 규칙과 배경을 추가합니다.
5. **복사해서 AI에 사용**을 눌러 사용할 AI에 붙여넣습니다. 배경·프로젝트 규칙이 있으면 함께 복사합니다.
6. 다듬고 싶으면 **Support**로 개선안을 받아 직접 가져오거나 복사합니다. 사전 평가나 세션 생성이 필요하지 않습니다.
7. 점수가 궁금할 때만 **선택 점검**을 엽니다. 세션을 선택하면 점검 이력이 SQLite에 저장되고, 세션이 없으면 현재 화면에서만 참고합니다.

```bash
python run.py
# 포트가 사용 중이거나 별도 저장 위치가 필요한 경우
python run.py --port 8877 --data-dir "D:/PromptCoachData"
# 자동 브라우저 실행 생략
python run.py --no-browser
```

종료는 실행한 터미널에서 Ctrl+C입니다. 인터넷에 배포하지 않는 **본인 PC용 로컬 앱**으로, 서버는 127.0.0.1에만 연결됩니다.

## 평가 방식 설정

### 설치 직후 — 규칙 기반 점검

처음 실행하면 **AI가 아닌 규칙 기반 점검**이 선택됩니다. 요청 동사, 환경·제약·출력·검증 표현과 예시 표지의 존재를 점검합니다. 인터넷과 API 키 없이 전체 UI와 저장 기능을 사용할 수 있지만, 의미·사실·모순·예시 품질을 판단하지 못합니다. 이 점수는 실제 AI 평가와 구분해서 기록합니다.

### Ollama — 실제 로컬 AI 평가

1. [Ollama](https://ollama.com)를 설치합니다.
2. 터미널에서 모델을 다운로드합니다. 설치한 Ollama와 장치에서 지원하는 모델을 선택하세요.

```bash
ollama pull qwen3:8b-q4_K_M
```

3. Ollama가 실행 중인지 확인합니다. 필요한 환경에서는 `ollama serve`를 실행합니다.
4. 앱의 **평가 설정**에서 `Ollama`를 선택합니다.
5. 모델 드롭다운에서 `qwen3:8b-q4_K_M`를 선택하고 API 주소 `http://127.0.0.1:11434`를 저장합니다.

현재 Qwen3는 빠른 응답을 위해 `think: false`로 요청합니다. 모델은 교체할 수 있으며 **JSON Schema 구조화 출력**을 지원해야 합니다. 모델 다운로드에는 인터넷이 필요합니다. 이후 프롬프트는 설정한 로컬 Ollama에 전달됩니다. 모델 속도와 장치 사양에 따라 대기 시간을 늘릴 수 있습니다.

### OpenAI 호환 API — 실제 외부 AI 평가

평가 설정에서 `OpenAI 호환 API`를 선택합니다.

- API 주소 예시: `https://api.openai.com/v1`
- 모델 예시: `gpt-4.1-mini` — 실제 계정에서 이용 가능한 구조화 출력 지원 모델로 변경 가능
- GPT-6 계열 선택지: `gpt-6.1-sol`, `gpt-6-sol`, `gpt-6-luna`. `gpt-6.1-luna`는 2026-11-04 기준 공식 문서에서 확인되지 않아 등록하지 않았습니다.
- API 키: 설정 화면에서 입력하거나 `OPENAI_API_KEY` 또는 `PROMPTCOACH_API_KEY` 환경변수 사용
- 평가 및 Support를 누르기 전에 편집기의 **외부 전송 동의**를 선택합니다.

프롬프트·배경·프로젝트 규칙이 설정한 API로 전달되며 이용료가 발생할 수 있습니다. API 키는 설정 파일이나 DB에 기록하지 않습니다. 화면에서 입력한 키는 서버 프로세스 메모리에만 유지되고 재시작하면 사라집니다. 환경변수에 등록한 키는 재시작 시 다시 읽습니다.

API 실패·시간 초과·스키마 오류·거절 시 오류를 표시합니다. 규칙 점검으로 조용히 전환하거나 실패한 점수를 저장하지 않습니다. 설정 저장은 연결 확인이 아니므로 첫 평가에서 실제 연결과 모델 호환성을 확인할 수 있습니다.

### Claude (Anthropic) — 실제 외부 AI 평가

1. **평가 설정**에서 `Claude (Anthropic)`를 선택합니다.
2. API 주소 `https://api.anthropic.com/v1`을 사용합니다.
3. AI별 모델 드롭다운에서 선택합니다. 기본 예시는 `claude-sonnet-5-5`입니다. 계정의 모델 이용 가능 여부와 요금을 확인하세요.
4. Claude API 키를 입력하고 설정을 저장합니다. 또는 실행 전에 `ANTHROPIC_API_KEY` 환경변수를 설정합니다.
5. 프롬프트 작성 화면에서 외부 전송 동의를 선택한 뒤 평가하거나 **Support**를 누릅니다.

Claude는 Messages API와 `output_config.format` 구조화 출력을 사용합니다. 해당 기능을 지원하는 모델이 필요합니다. 공급자·모델 이름과 당시 점수를 함께 기록하므로 성장 기록에서 평가 방식별로 필터링할 수 있습니다.

OpenAI와 Claude 키는 **공급자와 API 주소별로 분리**합니다. 공급자나 주소를 바꿔도 다른 주소의 키를 전달하지 않습니다. `OPENAI_API_KEY`와 `ANTHROPIC_API_KEY`는 각각 공식 기본 주소에만 적용합니다. 호환 API의 별도 주소에는 화면에서 해당 키를 입력하세요. `PROMPTCOACH_API_KEY`는 시작 시 저장되어 있는 외부 공급자·주소에만 적용합니다. 화면에서 입력한 키는 앱 재시작 후 다시 입력해야 합니다. 키 지우기는 선택한 공급자·주소에만 적용됩니다.

모델은 AI별 드롭다운으로 선택합니다. 목록은 `promptcoach/config.py`의 `PROVIDERS`에서 관리하며 계정 또는 설치된 모델을 실시간 조회한 결과는 아닙니다. 기존 설정에 저장된 별도 모델은 해당 공급자의 선택지에 유지됩니다. 규칙 기반 점검은 모델 선택을 사용하지 않습니다. Ollama는 선택한 모델을 먼저 `ollama pull 모델이름`으로 다운로드하세요.

서버 실행 중 모델 목록이나 예시 데이터를 수정했다면 서버를 재시작하고 브라우저를 새로고침하세요. 서버는 시작할 때 읽은 목록을 사용합니다.

## 주요 기능

| 화면 | 기능 |
| --- | --- |
| 프롬프트 작성 | 글자 수 제한 없는 편집, 초안 자동 저장, 배경·규칙 포함 복사 |
| 선택 점검 | 접힌 보조 화면에서 항목별 참고 점수와 개선 방향 확인 |
| 기법 분석 | 현재 요청에 사용한 것으로 보이는 기법 후보와 선택적인 추천 |
| Support | 평가 없이 현재 초안에서 개선안·변경 이유·질문 생성. 직접 선택해서 적용 |
| 버전 관리 | 개선안을 편집한 뒤 점검하면 같은 프롬프트의 새 버전 저장 |
| 성장 기록 | 프롬프트·세션·날짜별 그래프, Good/Normal/Bad 분포, 작성자별 요약 |
| 필터 | 프로젝트·작성자·세션·평가 방식·날짜·최신/전체 버전 |
| 평가 설정 | OpenAI·Claude·Ollama 선택, AI별 모델 드롭다운, 공급자·주소별 API 키 |
| 내보내기 | 선택된 기록의 JSON 내보내기, 전체 SQLite 온라인 백업 |
| 기법 라이브러리 | 17개 기법의 설명·사용처·한계, 기법마다 예시 드롭다운 3개(총 51개), 예시 프롬프트와 적용 포인트 |

초안은 같은 브라우저의 localStorage에 자동 저장됩니다. Support와 점검을 기다리는 동안에도 편집·복사할 수 있습니다. 늦게 도착한 결과가 편집 중인 내용을 덮어쓰지 않습니다. 개선안 요청 후 초안이 바뀌면 덮어쓰기는 막고 별도 복사는 허용합니다. **대기 취소**로 기다리기를 멈출 수 있지만, 이미 전송한 요청은 AI 서버에서 계속 처리될 수 있습니다.

AI Support는 원문을 그대로 보존하고, 결과를 바꿀 수 있는 핵심 누락·모호함을 최대 두 개의 짧은 `[직접 입력: ...]` 항목으로 덧붙입니다. 왜 필요한지와 확인 질문을 함께 보여줍니다. 기능·설계 패턴·기술·기한을 대신 정하지 않으며, 문맥에 답이 있거나 이미 명확한 요청은 불필요하게 바꾸지 않습니다.

초안 Support는 평가 기록을 만들지 않으며, 개선안은 현재 화면에서 확인·적용·복사합니다. 세션을 선택해 실행한 점검 기록은 SQLite에 저장됩니다. 브라우저 저장 공간이 부족하면 현재 내용을 복사해 보관하세요.

기법 라이브러리의 각 카드에서 **예시 선택** 드롭다운을 열면 번역·개발·글쓰기·분석 등 상황별 예시를 볼 수 있습니다. 선택한 프롬프트와 적용 포인트만 펼쳐지고, ‘예시를 선택하세요’로 돌아가면 다시 숨겨집니다. 예시는 학습 자료이며 AI를 호출하거나 실행 결과를 보장하지 않습니다. 내용은 `promptcoach/examples.py`에서 관리합니다.

## 입력 길이와 모델 처리 범위

작성창의 24,000자 제한과 별도 배경·프로젝트 규칙의 10,000자 제한을 제거했습니다. AI와 관계없이 전체 내용을 편집·복사할 수 있습니다. AI 처리에는 해당 모델의 문맥 한도가 적용되며, 로컬 HTTP 요청의 메모리 보호 한도는 16 MiB입니다. 매우 긴 내용이 처리되지 않아도 초안은 유지됩니다.

## 점수의 의미

점수는 **실행 전 요청 작성 준비도**이며, 실제 결과의 성공 확률이나 개인의 전체 실력 등급이 아닙니다. 짧고 명확한 단순 요청에 불필요한 예시나 검증 절차를 요구하지 않도록 적용 여부를 판정합니다. 역할·기법 개수·문장 길이에는 별도 가점을 주지 않습니다.

| 평가 항목 | 기본 가중치 |
| --- | ---: |
| 목표 명확성 | 24 |
| 관련 문맥 | 20 |
| 범위와 제약 | 16 |
| 결과 형식 | 16 |
| 검증 기준 | 16 |
| 예시 적합성 | 8 |

항목별 0~5점, 필요하지 않은 항목은 N/A로 제외합니다. 목표 명확성은 항상 평가합니다.

`총점 = Σ(적용 항목 점수 ÷ 5 × 가중치) ÷ Σ(적용 항목 가중치) × 100`

- **Good:** 80점 이상
- **Normal:** 55점 이상 80점 미만
- **Bad:** 55점 미만

모델이 반환한 총점 대신 서버가 항목 점수로 계산합니다. 원문과 일치하는 근거는 ‘원문 인용’, 바꿔 쓴 근거는 ‘AI의 해석’으로 표시합니다. 인용 불일치로 평가 전체를 거부하지 않습니다. 잘못된 점수·누락·중복 항목 등 실제 응답 오류가 발생해도 편집·복사는 계속 사용할 수 있습니다. 규칙 기반 점검의 빈칸 `[직접 입력: ...]`은 충족한 조건으로 가점하지 않습니다.

AI는 평가 대상의 지시를 수행하지 않도록 안내받지만, 모델의 의미 판단이나 점수 조작 방어가 완전한 것은 아닙니다. 고정 연습 과제와 사람의 검토를 함께 사용해 평가 기준을 보정하세요. 모델에 따라 점수가 다르며 이력에 평가 방식·모델·루브릭 버전을 보존합니다. 서로 다른 방식이 섞이면 대시보드에서 경고합니다.

### 이력 집계 기준

- 시간은 **UTC+09:00**으로 기록합니다. OS 시간대가 달라도 동일합니다.
- 날짜 필터는 양 끝 날짜를 포함합니다.
- 기본값은 **선택한 필터 범위 안에서 프롬프트별 최신 버전**입니다. 재평가를 많이 했다는 이유로 같은 초안이 평균을 과도하게 차지하지 않도록 합니다.
- 개선 전후 과정을 모두 보려면 **모든 평가 버전**으로 바꿉니다.
- 세션은 사용자가 직접 만드는 연습 단위이며, 브라우저 탭이나 대화 기록을 자동 수집하지 않습니다.
- 세션 추이는 선택한 기록에서 처음 평가가 발생한 순서입니다. 날짜 추이는 날짜순입니다.
- ReAct·RAG·ToT·체이닝은 텍스트에서 의도를 감지할 수 있지만 실제 검색·다중 호출·도구 실행을 했는지는 이 앱이 확인하지 않습니다.

## 저장과 백업

기본 저장 위치는 실행 폴더 아래입니다.

```text
data/
  coach.sqlite3     원문·점수·버전·프로젝트·작성자·세션·Support
  settings.json     모델·주소·타임아웃 등 비밀이 아닌 설정
```

SQLite는 WAL 모드입니다. **실행 중 .sqlite3 파일만 복사하지 말고** 성장 기록의 DB 백업 버튼을 사용하세요. 백업 API는 SQLite의 backup 기능으로 커밋된 데이터를 포함한 일관된 파일을 생성합니다.

복원 방법:

1. 앱을 완전히 종료합니다.
2. 기존 `coach.sqlite3`, `coach.sqlite3-wal`, `coach.sqlite3-shm`이 있다면 별도 백업 폴더로 함께 이동해 보관합니다.
3. 다운로드한 백업 파일을 저장 위치에 `coach.sqlite3`라는 이름으로 둡니다.
4. 앱을 다시 실행합니다.

백업 DB에는 원문과 평가·개선안이 포함됩니다. 설정 파일과 브라우저 초안은 DB 백업에 포함되지 않습니다. JSON은 선택한 기록의 분석·교환용이며 현재 버전에서 JSON 재가져오기는 제공하지 않습니다.

## 개인과 팀 사용 범위

한 PC에서 여러 작성자를 등록하고 프로젝트별 규칙과 세션을 나눠 사용할 수 있습니다. 각 팀원이 자신의 PC에서 실행할 수도 있습니다. **작성자 이름은 인증 계정이 아니며**, 다른 PC와 자동 동기화하지 않습니다. 실시간 공동 사용이나 사용자별 접근 제어가 필요하면 인증·중앙 저장소·HTTPS 서버를 추가해야 합니다. 현재 앱을 그대로 외부 네트워크에 노출하지 마세요.

## 테스트

프로젝트 루트에서 실행합니다.

```bash
python -m unittest discover -s tests -v
python -m compileall -q promptcoach run.py
```

평가 범위·점수 계산·근거 검증·버전 보존·중복 요청·문맥 스냅샷·팀/날짜 필터·백업·API 오류·로컬 HTTP 흐름을 테스트합니다. 실제 AI 모델의 의미 평가 품질은 연결한 모델과 별도의 평가 데이터로 확인해야 합니다.
